# Claude Code 背后那个人，说了一句让程序员很不爽的话

前几天我翻了一场采访，主角叫 Boris Cherny。

他是谁？Claude Code 的产品负责人。

没听过？没关系。你只要知道一件事就够了——

他先去了 Cursor，又跑回了 Anthropic。

就像一个人先去了清华，又退学回去复读，最后考上了北大。

这种人说的话，你可以不同意，但你很难说他没资格讲。

而他确实说了一句让程序员很不爽的话：

**"编程问题，已经被解决了。"**

这话要是别人说的，评论区早就开骂了。

但说这话的人，是亲手把 Claude Code 做出来的那个人。

## 1

先说一个很多人不知道的事。

Claude Code 一开始，不是一个精心规划的大产品。

它更像是先把最小的东西扔出来，然后不断试、不断改、不断删。

Boris 的思路不是先画蓝图再死磕实现，而是：

先把东西扔出来 → 让它进入真实工作流 → 看模型能做什么 → 再决定留什么、删什么。

这很 AI 原生。

不是"人先定义好一切"，而是"模型能力在推着产品走"。

就像养狗——你不能先规划好它一辈子的行为。你得先放它出去跑，看它擅长什么，再决定训练方向。

Boris 之所以敢走这条路，是因为他先在 Cursor 待过。

看清楚了那条路的天花板，才回来走这条。

他不是没选过。他是选过了才放弃的。

这比没选过就放弃的人，多了一层东西——

叫做资格。

---

## 2

现在说三个值得记住的事。

第一件，Claude Code 不是更好的编辑器，是更懒的老板。

AI 编程工具现在满大街都是。Cursor、Copilot、Windsurf、Kiro——大家都在卷谁更像一个"聪明的编辑器"。

但 Boris 根本没往这条路上走。

Claude Code 不是把 AI 塞进编辑器，而是把你从编辑器里拉出来，放到更高一层的位置上。

Cursor 是"AI 进入编辑器"。Claude Code 是"AI 接管工作流"。

编辑器里，你还是那个干活的人，AI 帮你打字更快。

工作流里，你变成了下需求的人，AI 变成了干活的人。

这就像雇了一个不用睡觉的实习生——但这个实习生比你聪明，而且不会因为你改了三次需求就在背后骂你。

程序员不爽的是什么？

不是 AI 写代码比他快。

是他突然发现，自己从"干活的人"变成了"下需求的人"。

这感觉，就像你当了十年厨子，突然有一天老板说，你去前台点菜吧，厨房交给机器人了。

你做的菜不好吃吗？不是。

是老板觉得，让机器人做，更省心。

---

## 3

第二件，终端不是老派，是唯一不会骗你的界面。

很多人看到 Claude Code 用终端，第一反应是：都什么年代了，还做终端？

但 Boris 偏偏选了终端。

这不是怀旧，是判断。

终端天然适合：接收命令、处理上下文、连续执行多步、输出可追踪结果。

而 Agent 型产品最怕的就是——你不知道它在干嘛。

GUI 让你觉得一切尽在掌控。漂亮的按钮、流畅的动画、看起来很专业的仪表盘。但你不知道背后到底发生了什么。

终端不一样。它在干嘛，你就看到什么。

这就像买车：仪表盘漂亮的车不一定好开，但你能听到发动机声音的车，更知道它在干嘛。

终端不酷，但终端诚实。

在 AI 还不够可靠的阶段，诚实比好看重要。

你愿意坐一辆仪表盘漂亮但不知道刹车灵不灵的车，还是愿意坐一辆不好看但发动机声音正常的车？

Boris 选了后者。

因为他从 Cursor 跑回来的那一刻就知道了——

好看的东西，不一定好用。好用的东西，一定不难看。

---

## 4

第三件，也是最反直觉的一件。

Claude Code 最值钱的能力，不是写代码，是说"不"。

你以为 AI 编程工具最有用的时候，是它帮你把活干了。

不是。它最有用的时候，是它拦住你犯蠢。

好的合伙人不是什么都答应你的人，是拦住你犯蠢的人。你身边最好的同事，不是干活最快的，是能在你脑子一热的时候说"等一下"的那个人。

Claude Code 有时候就是那个说"等一下"的角色。

一个会说"不"的工具，比一个只会说"好的"的工具，值钱太多了。

Boris 把这个做进了产品里，不是因为他理想主义。

是因为他自己就是那个被"拦住"过的人——他短暂去过 Cursor，又回来了。

他比大多数人更清楚"选错了路"是什么感觉。

## 5

现在说回那句话。

**"编程问题，已经被解决了。"**

代码生成确实变快了。但软件工程从来不只是写代码。需求定义、系统边界、测试覆盖、技术债——这些东西 AI 还远远没"解决"。

生成代码变便宜了，但判断代码对不对，还是很贵。

这句话更像一个方向判断，不是终局判断。

Boris 自己也知道，因为他团队里还有工程师在写代码。

他不是在说"程序员没用了"。

他是在说：软件工程的重心，正在从"写代码"转向"组织智能"。

你品品这两句话的区别。

"程序员没用了"——这是挑衅。

"写代码不再是核心能力"——这是判断。

Boris 说的是后者。

但大多数人只听到了前者。

这就是为什么我说，你可以不同意他，但你最好先想清楚，他为什么敢这么说。

---

## 6

再补一个容易被忽略的事。

Boris 说给团队更多资源能做出更好的 AI 产品。

不一定。方向不对，钱越多死得越快。

Claude Code 成功不是因为 Anthropic 有钱，是因为他们够克制——没把产品做成臃肿的 IDE，让它跟着模型能力一起长。

克制比有钱难多了。

你见过多少公司，钱烧完了，产品做了一堆功能，用户打开一看——

这什么玩意儿？我就想写个代码，你给我整了个航天飞机的驾驶舱。

Boris 从 Cursor 跑回来，他亲眼见过资源多但方向拧巴是什么样子。

所以他选了一条更难的路——不是做更多，是做更少。

不是功能堆满屏幕，是让模型能力推着产品走。

这就像装修房子：不是把所有好看的家具都搬进去，是留白，让住在里面的人自己定义空间。

好的产品不是功能多的产品，是用户用着舒服的产品。

## 7

最后说一件事。

Boris 和 Anthropic 现在在聊的，不只是编程工具。

他们在聊 AI 协作、工作流编排、Agent 参与决策。

但如果你自己不知道要什么，Agent 只能帮你更快地做错事。

就像导航软件：它能帮你找到最快的路，但你得先知道自己要去哪。

AI 编程工具已经不是"有没有 AI"的阶段了。

它进入了"谁更会组织智能"的阶段。

Claude Code 不是一个功能，是一种新的软件工程姿势。

它不是在帮你写代码。它在帮你思考。

Boris Cherny 那句话，现在你再听一遍：

> "编程问题，已经被解决了。"

刺耳吗？刺耳。

但说这话的人，先去了 Cursor，又回到了 Anthropic。

他不是在吹牛，他是用脚投票投出来的。

你可以不同意他。

**但你最好先想清楚，他为什么敢这么说。**

因为他选过了，又放弃了，又选了。

这种人的判断，值得你多想三秒。
